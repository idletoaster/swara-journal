# Disaster Recovery — swara-journal

## Where data lives
- **Code:** this GitHub repo (idletoaster/swara-journal)
- **Live SQLite DB:** `journal.db` on disk (NOT in git)
- **Restic backup:** google-drive:backup/swara-journal  (5-day retention)
- **Backup cron:** 30 3 * * *   /home/pawan/bin/backup-45.19.sh

## What is captured by restic
The whole `~/swara-journal` tree, **except**:
- `node_modules/`  (regenerated by `npm install`)
- `.git/`          (this is on GitHub, no need to back up)

So the captured non-regenerable assets are:
- `journal.db`           — SQLite user data
- `package.json`         — drive dependency versions
- `server.js`            — code (mirrored on GitHub)
- `public/`              — static PWA assets

## On a fresh Ubuntu host
1. `apt install -y restic && (curl -fsSL https://rclone.org/install.sh | sudo bash)`
2. Clone the code:
       gh repo clone idletoaster/swara-journal
3. Drop the rclone config and the restic passphrase file:
       ~/.config/rclone/rclone.conf     (mode 600)
       ~/.secrets/restic_passphrase_swara-journal   (mode 600)
4. Restore the live data on top of the clone:
       restic -r "rclone:google-drive:backup/swara-journal" \
              --password-file ~/.secrets/restic_passphrase_swara-journal \
              restore latest --target /
5. `cd ~/swara-journal && npm install`     # rebuilds sqlite3 native binding
6. `pm2 start server.js --name swara-journal`

There's also a wrapper script on the source server at
`/home/pawan/restore-45.19.sh` that does steps 3–4 for both repos.
